Submit 必须先预览。预览包含适配范围内净差异、全部说明、可展开完整快照、实例/共享影响、源基线、去向、执行意图和 v2 的 GM 引用。确认发送同一份冻结载荷。取消不发送、不创建待确认记录。内容、基线、目标桥接改变需重新审阅；主题和导航不影响预览。删除对象的说明必须明确重新关联或移除。

保留 v1；v2 新增 GM 只读就绪检查、显式映射、分类型反馈路由和独立证据回写。原 GM 的 PLAN/GAP 是权威，不另建规划器或任务库。

## 立即本地试用

已包含编译好的前端，不必先安装 npm 依赖。macOS/Linux 具备 Python 3.10+ 时，在解压后的目录运行：

```sh
python3 bridge/server.py
```

打开命令显示的 `http://127.0.0.1:8765`。默认是本地桥接演示模式：SQLite 保存收单记录，但没有模型或游戏写回。

需要开发、重建与回归时，使用 Node 22+：

```sh
npm ci
npm run build
npm run check
npm test
```

所有浏览器草稿和说明只在当前浏览器；私有站点不等于云端同步。清除浏览器数据前请导出草稿。

## 真实本地连接

按 `LOCAL-SUBMIT.md` 绑定已有、空闲且目录匹配的 Codex 线程；使用原游戏源码目录。工作台和其 SQLite 状态文件应放在游戏源码目录之外，避免把桥接自己的状态变化混入游戏文件范围审计。v2 还要求确切 GM 工具/技能版本、真实运行能力、已审阅的服务端目标映射和相应阶段的人类确认。映射结构和正式结果导入见 `GM-ADAPTER-V2.md`。

```sh
python3 bridge/server.py --mode codex --thread 已有线程ID \
  --project-root /实际游戏源码目录 --state /私有目录/workbench.sqlite3
```

上面是启动说明，不是本次已执行的真实连接。原游戏源码来自既有游戏交付包；此包是工作台完整源码，不重复打包整套游戏源码。

## 验证与真实边界

- 当前私有网页仍明确标注浏览器本地演示，没有 Agent、Godot 或真实 check run
- 单元、DOM、协议、持久化恢复及反例测试通过，详见验证报告
- 实际 Codex→GM→Godot 回合没有在本任务中执行，因此不能说真实联动或游戏体验验收通过
- 云浏览器无法连接执行工作区的本地预览；没有冒充渲染截图或手机视觉验收
- 正式 GM run 的验证可独立导入并显示 PASS / FAIL / BLOCKED / ERROR；收单、送达、回合完成、逐项落实与人类确认互相独立
- 通用文件变化或全局测试成功不能证明每条自然语言意图已落实；没有充分逐项语义证据时保持待核对，而非宣称完成
- 结果不会覆盖提交之后的新草稿；重新提取源基线也不会自动替换用户草稿
