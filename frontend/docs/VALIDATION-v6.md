# v0.6 · 评论覆盖与工作区减负

## 本轮范围

评论是绑定到当前目标、提交给 Agent 的用户修改说明，不是多人讨论系统。复用浏览器本地存储，没有新增服务器数据库、真实模型调用或游戏写回。

目标目录共 183 项：项目 1、场景 5、背景 5、场景实例 93（含入口、出口）、独立有向过渡 9、共享定义 21、行为 38、共享过渡预设 2、生成规则 9。数量代表模型中实际可寻址目标，不代表 183 个类型，也不包括运行中尚未连接的临时实体。隐藏投射物/效果资源入口可转到对应共享定义评论。资源缩略图、来源链接和诊断文本是所属目标的上下文，不伪造额外游戏实例。

预设保持只读；评论不会偷偷修改所有引用的参数。生成规则保留真实源引用、条件、定义和未连接的运行时状态。预设没有伪造 Godot source mapping，mask_wipe 的 maskResourceRef 仍为 null。

## 操作路径

- 顶部：项目、名称/ID 搜索、日夜切换、草稿目标数、预览提交。在线版显式标记演示。
- 左侧：可折叠导航。场景、对象列表分组展开，资源新增与浏览分开；草稿保存/打开、撤销在导航中。
- 中央：当前场景、连接、定义或行为工作区。
- 右侧：单一当前详情；评论入口在顶部，显示完整稳定 ID、目标路径、实例或共享范围。只读数值也能评论。属性、源证据、诊断逐层展开。
- 集中申报单：独立模态；查看所有已写评论、显式处理孤儿说明、预览全部净差异后确认。协议、正式反馈与执行日志位于二级折叠区。
- 窄屏：工作区与当前详情互相切换，详情有返回按钮；导航为全宽列表，不把三列压在同一屏。

## 保存和刷新

每次评论 input 事件立即带原始目标 ID 保存，不等 blur，不依赖重新选择的当前 scope。切换和重建 DOM 从内存/本地存储读取同一目标说明。存储失败时明确提示仅当前页面保留。

评论自动保存；场景/参数草稿仍采用原有显式保存与重新打开机制。刷新不会假装已自动恢复未保存布局；新建目标未恢复时，其评论保留并显示为待处理孤儿，必须明确重关联或移除。撤销/重置不将旧评论重绑到项目。

## 提交边界

连接支持时默认 v2。预设、生成规则和过渡必须使用精确 v2，v1 不把它们降级为项目授权。所有非空说明都进入同一冻结预览，零参数变化的 notes-only 提交可用。纯导航、主题切换不改变冻结预览；评论/数据/已审阅上下文改变立即失效。取消不产生 POST；确认逐字发送预览载荷，重复点击由现有互斥/幂等逻辑保护。

服务器权威基线、target mappings、allowedSourcePaths、allowedDiffPaths、规范/权限摘要、GM 阶段确认和拒绝路径未放宽。没有服务器审阅映射的目标可评论并在演示中收单，但真实执行仍为 BLOCKED。在线演示收据保持 NOT_DELIVERED、NOT_STARTED、BLOCKED、certified=false，不能当作真实 Agent 或 Godot 结果。

## 验证方法与限制

v5 改动前完整测试先通过，并建立本地 checkpoint。v6 保留旧测试的交互/提交语义，更新因新布局改变的选择器和默认协议步骤；新增全 183 目标评论矩阵、批量 notes-only 冻结预览、Python 基线校验、跨目标隔离、孤儿恢复、单一输入和模态结构覆盖。

实际渲染未通过环境门槛：云浏览器访问 executor 本地预览端口返回 ERR_CONNECTION_REFUSED；同一预览探测的提权命令遇到沙箱挂载错误。没有把 jsdom、CSS 规则或结构检查称为视觉验收，也没有伪造截图。真实窄屏布局、屏幕阅读器、IME 和原生浏览器拖拽仍需实际浏览器复验。

本轮未运行真实模型、真实 GM/Godot 写回、formal check 或游戏运行。既有 v5 的真实执行链条限制继续有效，见 chain-boundaries-v5.md。
