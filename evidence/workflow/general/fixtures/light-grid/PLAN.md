# Current Tag Plan

**Tag:** v0.1.0

## Game Description
A small 2D puzzle in a fixed 960×540 window. Clicking a square toggles its light and its orthogonal neighbors. Turn every light off to win. Display moves, concise instructions, a Reset button, and a win message. Use procedural squares and labels without external assets, plugins, network, or audio. This is an open 2D Godot project described by stable object and requirement IDs, not a genre preset.

## Tag Mechanics
- [main-scene-M1] For the isolated MVP, create scenes/main.tscn and its coordinator, establish the fixed 960×540 non-resizable window, and compose the procedural board and HUD with sufficient space for all states. (task: compose-main-scene; object IDs: main-scene, puzzle-board, hud; requirement IDs: project-scope, fixed-window, separate-responsibilities).
- [rules-M2] Implement the independent puzzle model, in-bounds orthogonal toggles, known-sequence start generation, move counting, solved detection, post-win move rejection, and deterministic reset. (task: implement-puzzle-rules; object IDs: rules; requirement IDs: toggle-rule, solvable-start, move-count, win-state, reset-controls, separate-responsibilities).
- [puzzle-board-M3] Build nine procedural square buttons with ON/OFF labels and interaction feedback. Render supplied puzzle state, emit selections, reflect win locking, and read the editable accent choice through StudioRuntime.object_value(). (task: render-puzzle-board; object IDs: puzzle-board; requirement IDs: project-scope, board-layout, editable-accent, win-state, separate-responsibilities).
- [hud-M4] Create the title, concise instructions, move counter, Reset button, and conditional win message. Update them from supplied state and emit reset requests. (task: build-puzzle-hud; object IDs: hud; requirement IDs: fixed-window, move-count, win-state, reset-controls, hud-content, separate-responsibilities).
- [main-scene-M5] Route cell selections and Reset requests through the coordinator to the rules. Handle a reset input action mapped to R in puzzle_input.gd, ignore key repeats, and refresh the board and HUD together after every accepted operation. (task: connect-input-and-state; object IDs: main-scene, puzzle-board, rules, hud; requirement IDs: toggle-rule, move-count, win-state, reset-controls, separate-responsibilities).
- [main-scene-M6] After isolated implementation, perform the specified manual gameplay and visual checks and record observations and unresolved issues. This planning task does not establish that checks have passed or authorize production work. Do not perform build hash checks. (task: review-isolated-gameplay; object IDs: main-scene, puzzle-board, rules, hud; requirement IDs: fixed-window, board-layout, toggle-rule, solvable-start, move-count, win-state, reset-controls, hud-content, editable-accent, manual-gameplay-review).

## Component Coverage
- `main-scene` (scene): Light Grid Main Scene. Owns scene composition and coordinates input, puzzle state, board rendering, and HUD updates. Input actions are handled separately in puzzle_input.gd. Sources: scenes/main.tscn, scripts/main.gd, scripts/puzzle_input.gd.
- `puzzle-board` (entity): Puzzle Board. Renders nine square buttons in three rows and three columns. Emits cell selections and displays state supplied by the rules. Lit squares use the chosen accent; unlit squares use a dark neutral fill. ON and OFF labels distinguish states independently of color. Sources: scripts/puzzle_board.gd.
- `puzzle-board.accent-color` (choice): Accent color; current value `"#38BDF8"`; editable `true`.
- `rules` (rule): Lights Out Rules. Owns the nine light states, legal toggles, deterministic start generation, move count, solved detection, and reset. Contains no rendering or input handling. Sources: scripts/rules.gd.
- `hud` (interface): Puzzle HUD. Displays Light Grid, instructions, move count, Reset, and the win message. Emits reset requests without mutating puzzle state. Sources: scripts/hud.gd.
