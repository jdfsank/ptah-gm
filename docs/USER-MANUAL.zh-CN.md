## 工作台能做什么

新建项目采用 `objects-v1` 通用对象流程，目标是用稳定对象 ID、属性、关系、文件绑定和需求描述一个 2D Godot 游戏。对象可以是场景、实体、机制、规则、界面、素材或内容。流程不按游戏类型设置固定产品路径；策划 session 根据你的概念整理问题、对象文档和制作任务。

当前实现范围仍有限：只支持 Godot 4 的 2D GDScript 工程；可写文件限于 `project.godot`、`scripts/**/*.gd`、`scenes/**/*.tscn`、`resources/**/*.tres` 和 `assets/` 下 PNG/JPEG/WebP。不能在工作台里添加插件、编辑器插件、测试程序、音频管线或任意可执行文件。图片可作为本轮参考输入，上传本身不会生成或自动导入新美术。

已存在的旧 collect-loop 项目保留原工作流和参数。新工作流不会把旧项目或旧批准自动转换成通用对象项目；对象工作流只能用于已标记为 `objects-v1` 的项目。旧版 `/legacy/` 页面仍是历史只读入口。

## 管理项目

打开本机部署者提供的 Studio 地址，通常为 `http://127.0.0.1:8765/studio/`。如果页面出现“测试工作区”横幅，该环境中的批准和发布都是测试数据。正式接受候选前，确认当前连接的是正确的生产工作区。

首页先显示项目列表，不自动进入最近的讨论或失败任务。在“新项目名称”填写名称并点“创建项目”，得到一个独立空项目。此时还没有策划方案，也没有启动 agent。继续已有项目时，使用对应项目的入口；项目页可重命名、归档或返回“所有项目”。归档保留历史，有活动或未知执行时先停止或核账。附件、草稿、对象和制作记录只属于对应项目。

项目页面链接带有项目和阶段身份；刷新同一链接继续该项目，打开首页则重新选择。切换不会取消已启动的后端作业；等待中的结果仍保存在原项目。查看某个项目的制作记录会进入它所属的项目，不能把结果带到另一个项目。

## 从概念开始

在项目的初始阶段，用“用户原始想法”说明游戏的核心体验、玩家动作、目标、失败条件和希望先验证的范围。也可以选择“概念参考”“风格参考”“布局参考”或“素材输入”后添加图片。页面文字框最多 5,000 字；每轮最多六张 PNG/JPEG/WebP 图片，每张最多 5 MiB。图片创建时绑定当前项目，是否进入制作范围会显示在提案中。

点“梳理我的想法”后，服务会启动一个独立的**只读策划 session**。它只整理问题和计划，不会改项目文件。状态为“策划中”时，页面会轮询提案；若结果是“需要补充信息”，按问题要求选择选项、填写文字或数字，再点“提交回答”。提交回答会开启下一轮策划，并更新方案修订。若状态为 `BLOCKED`，先阅读阻塞原因；不要通过重复点提交来绕过边界。

策划准备好后，页面显示“方案待确认”。先读完整计划、GDD/计划章节、对象与关系、字段、源文件绑定、制作任务、验收条件和对象差异。方案如果遗漏了你重视的内容，返回补充概念或回答问题。只有你确认准确后，勾选“我已阅读并确认上面的方案和制作范围”，再点“确认方案并继续”。这会冻结当前修订、Git 基线、制作范围和验收条件，供另一条制作 session 使用。生产路径还会把冻结的 GM 规格交给仓库绑定的 GodotMaker non-pk 审批检查；这项检查绑定当前项目与提案记录，不能用模型的文字回复代替。测试数据不能通过生产 GM 规格门。

页面按步骤展开：讨论时只显示用户输入与 AI 问题；只有完整合法方案 READY 后才显示 AI 方案和确认制作动作。讨论记录保留在项目后端，页面优先展示当前轮次；后续制作和候选区域不会提前显示。信息块分别标注用户、AI 策划、AI 制作和系统验证，概念原文不是 AI 生成方案。

## 看懂顶部工作状态

项目页面最上方的状态栏显示当前阶段、正在等待谁和下一步。等待你回答、等待你审阅、等待 AI 策划反馈、等待 AI 制作，以及系统验证是不同状态。状态由本项目的提案和作业记录决定；AI 文本中的“完成”不代表已经验证或接受。

连接中断或请求结果未知时，页面显示状态未确认。先刷新或使用原执行的核账入口，不要重复提交。停止状态尚未确认时仍保留项目占用；原执行真正停止后才能开始下一轮。

## 制作、验证与候选决定

冻结后，工作台按“排队中 / 准备制作 / 制作中 / 运行验证 / 整理结果”显示进度。策划和制作由不同 session 执行：策划只读，制作按冻结表单修改游戏工程。生产 session 的完成回复只代表回合结束，不代表文件已正确修改或游戏通过验证。

候选页提供 Git 版本、对象映射、可编辑能力、变更摘要和验证证据。验证器运行的目标包括写入范围、冻结对象文档与文件绑定、干净 Godot 导入，以及后端自带的主场景加载、实例化和短暂运行冒烟。它不会运行制作方指定的测试脚本，也不会凭制作方输出的 PASS 标记判定通过。

**技术 PASS 不代表玩法验收。**它只表示报告中实际运行并记录的技术检查通过，包括 Git 写入范围、冻结对象与源绑定、干净导入和后端主场景短运行冒烟。主场景启动不能证明操作、碰撞、关卡路线、胜负、重置、视觉质量或手感正确。报告中的 `NOT_TESTED` 项需要你在 Godot 中实际体验；不要把制作 session 的 `completed` 或测试探针的合成接受当作自己的验收。

在候选页先使用“在 Godot 中运行此候选”亲自体验，再选择：

- **接受并发布此版本**：接受这个项目快照，更新工作台当前版本。
- **拒绝此候选**：保留原发布版本，当前候选不成为工作台版本。

接受是用户对候选的决定；它不是 Godot 导出、签名、上架或对外发布游戏，也不是 GM 全流程发行认证。评审时按本轮计划逐项检查：核心动作是否可用、开始和结束状态是否清楚、失败后能否恢复、对象与要求是否落实、画面是否易懂。体验后如果有问题，拒绝候选或在当前版本上整理下一轮修改。

如果首个 Demo 尚未被接受，制作作业以“制作失败”结束，工作台会保留失败诊断，并提供“沿用原输入重新策划”。点击后，原批准表单里的用户文字和本项目参考图会复制回可编辑的初始概念；你可以先修改，再手动点“梳理我的想法”开始新的策划。该操作不会自动重开策划或制作，也不会复用旧冻结表单。迭代阶段的制作失败仍从当前对象工作台提出新一轮调整。

## 对象级精细迭代

首个候选通过技术验证并被你接受后，初始阶段显示“进入迭代工作台”链接。未接受的候选不能成为迭代基线。后续候选被拒绝或制作失败时，当前已接受版本仍可继续调整。

进入迭代工作台后，在“项目对象”中选择需要调整的对象。界面将对象导航、当前版本上下文/预览、属性与反馈分区展示；窄屏依次排列。界面显示对象说明、父对象、关系、绑定源文件及服务声明的字段。未声明可编辑能力的字段会保持只读或不显示为可编辑项。初始讨论保留为项目历史，不在这里要求重新描述整个游戏。

在“提出下一步调整”可以同时提交三类信息：

1. **自然语言说明**：描述对象要怎样变化，最多 3,000 字。
2. **明确属性值**：只提交你实际编辑过的字段；未改动的数值不会覆盖计划中的现值。类型、选项和范围由服务端校验。
3. **对象反馈**：将问题关联到所选对象，选择“一般、问题、视觉、行为”类别并填写文字。反馈与字段修改分开保存。

按“整理本轮调整”后，策划会收到当前发布修订、Git 基线、目标对象、实际字段修改和独立反馈。它会返回新的问题或完整计划。再次核对对象 ID、字段值、任务和验收范围，然后确认冻结；制作 session 会使用另一份新表单。自然语言不会自动扩大后端写入白名单。范围外要求会要求澄清或阻塞。

### 常见调整示例

- **数字字段：**在 Bridge Runner 的“Player”对象把 `speed` 从 220 改为 300 px/s，`jump-speed` 保持 420。数字和整数值必须满足字段声明的最小值、最大值和步长；越界或类型错误会在服务端拒绝。字段值会存入对象文档，游戏代码应通过受保护的 `StudioRuntime.object_value()` 读取它。
- **选项字段：**在 Light Grid 的“Puzzle Board”对象选择 `accent-color` 的一个现有颜色选项。选项字段只能选择计划列出的值，不能在此输入新的任意颜色。若策划为别的字段声明了颜色类型，可使用 `#RRGGBB` 或 `#RRGGBBAA` 格式。
- **布尔、文字、坐标：**计划可声明 true/false 开关、文字字段或由两个有限数字组成的 `vector2`。文字可为空；每个字段仍受类型和长度限制。字段是否能在工作台中编辑，以当前项目发布对象声明的能力为准。
- **关联反馈：**选择“Player”对象并提交“移动太快，窄平台上的落点不容易控制”，类别选“行为”；或选具体界面对象并说明文字遮挡了按钮，类别选“视觉”。反馈绑定对象并与字段值分开保存，不会因为它指向某个对象就自动批准实现。
- **自然语言与字段一起调整：**可把 `speed` 设为 300，并补充“保持跳跃力度、平台和控制键不变”。策划会将明确值和保留条件纳入新计划；确认前仍需检查完整对象差异和制作范围。

一次 r3 隔离探针实测了速度 220→300 px/s，并对玩家提交青色（`#00FFFF`）的定向视觉反馈。之后的修复复测确认该数值和颜色在重置修复后仍保留。Bridge Runner 的实际输入与物理检查记录了“首次通关→按 R 回到出生点和 playing→再次走完路线并重新 WON”；Light Grid 的真实 viewport 检查记录了角、边、中心点击效果和计步、三步解谜、胜利后的点击锁定，以及键盘 R 与 Reset 按钮的重置行为。可查看[Bridge Runner 检查记录](../evidence/workflow/general/bridge-gameplay-repaired-r2.json)和[Light Grid 检查记录](../evidence/workflow/general/puzzle-gameplay.json)。两者都是 test-only fixture 测试，不会把当前候选报告中的一般玩法要求从 `NOT_TESTED` 自动改成通过，也不代替你试玩和接受当前候选。

如果已有未提交草稿，而候选发布产生了新版本，先处理“检查草稿重关联”。页面会预览旧/新基线、字段差异和对象反馈。你可以选择“保留旧草稿”，或确认预览后用“预览后更新草稿基线”复制到新版本。重关联不修改已发布游戏；能力或类型改变的字段要先人工修复。预览后草稿若有变化，系统会刷新预览并要求再次确认。草稿重关联未完成时不能提交新迭代。

GameStudio 固定版本的核心规划和 playtest checklist 强调明确玩家动作、首屏状态、暂停/失败/恢复、界面可读性和可复现的试玩反馈；工作台把其中可复用的流程要求落在对象、字段、验收条件和反馈记录上。该参考默认的 Phaser 浏览器技术栈没有被引入 Godot 工程。

## 草稿、取消和状态恢复

概念草稿以及迭代文字、对象字段、反馈和选择保存在当前浏览器，并按服务存储身份、项目、阶段和版本区分。草稿不是服务端备份，也不会自动同步到另一台设备。存储不可用时，刷新页面可能丢失尚未提交的输入；重要内容请另行保存。

旧格式草稿缺少服务存储身份，升级后仍保留在浏览器中，但不会自动载入或认领到当前项目。这样避免复制或重建服务存储后，将另一套环境中的草稿带入同名项目。

已经冻结的表单保存在服务端。刷新后按页面给出的同一提案或制作表单继续，不要重新创建项目来绕过原状态。服务对未提交的策划和制作都维持唯一的执行记录；原生 session 停止状态未知时，不会自动重派。

“取消策划”或“请求取消”只是发出停止请求。只有确认受管进程组已停止后，服务才会解除项目占用。遇到“策划状态待核实”或“状态待核实”，使用相应的“对账策划状态”或“向服务对账此作业”。对账只观察原执行，不会重派，也不会杀掉无关进程。仍无法确认时，项目会继续受阻，请联系部署者。

策划失败时，“策划执行诊断”会显示失败原因、耗时、原生 session 和进程停止确认。连接中断或超时不表示游戏制作失败；这一阶段还没有制作表单。确认停止且可以重试时，点“使用原输入重试策划”，系统会在同一项目中使用原文字、参考图和对象变更创建新提案，保留旧失败记录。重试不会自动确认计划或启动制作。遇到登录、权限或输入准备问题时，先请部署者处理原因；停止状态未确认时先对账。

若原生 session 超时，但已经返回完整、校验通过的澄清问题，且停止和只读范围均确认，系统可以恢复这些问题。页面会明确提示原生策划未确认完成；回答表单可用，制作确认仍不可用。较早的失败记录可能提供“恢复已返回的澄清问题”，点击后只恢复问题，不复用未完成的对象文档和制作任务。你的回答会启动新的策划回合，完整制作计划仍需后续单独审阅确认。

若点击重试后出现“提交结果待确认”，请先点“刷新状态”核账。网络响应丢失时，服务端可能已创建新提案，页面会锁定原重试按钮以避免重复创建。刷新失败时锁定继续保留；刷新成功后采用服务端的新提案，或确认仍为原失败提案后允许重试。重新打开页面或选择项目也会显示该项目最新的失败诊断或待回答提案。

页面重开时按链接恢复明确的项目；首页不会自动恢复最近的提案。通过“所有项目”选择继续或新建。刷新只读取当前所选项目；旧项目的迟到响应不能改变当前界面。概念讨论、方案审阅、制作与验证、候选接受和迭代具有各自的状态说明。

## 旧项目和能力边界

- 新建项目使用通用 2D 对象工作流；既有 collect-loop 项目继续使用旧模板流程。
- 当前不是 3D 工具，也不提供任意游戏引擎、插件或编辑器扩展。
- 自动导入和运行冒烟不判断“好不好玩”；玩法和美术要求仍需用户实际体验。
- 图片是参考输入；美术生成、音频生成、导出、签名、商店发布和多人/远程工作流不在当前范围内。
- 本机执行面向合作型单用户使用。验证过程会运行项目的 Godot 代码；当前不能承诺抵御恶意游戏工程或提供 OS 级沙箱。
- 已有隔离证据覆盖两个不同玩法的原生制作 session、真实 Godot 技术检查和一次字段/反馈迭代；r3 状态为 `testData=true`、`productionAuthorized=false`，`humanAcceptance=NOT PERFORMED`。这不是生产批准，也没有完成玩法验收。
- Bridge Runner 曾有“获胜后按 R 返回出生点，却因旧出口接触立即再次进入 WON”的问题；修复版本的 fixture 专项真实 viewport 复测已通过。该记录不等于当前一般候选或生产版本的人工验收。
