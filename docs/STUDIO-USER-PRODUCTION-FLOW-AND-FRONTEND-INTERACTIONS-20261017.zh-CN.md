# Studio 当前用户制作流程与前端交互清单

归档日期：2026-10-17。内容来源：本对话中的流程与交互梳理。

本文依据归档时的 Studio 前端实现和项目公开状态整理，记录当前主要制作流程及相关入口；不是一次新的完整用户试用、技术验证或用户验收，也不替代原 125 项交互清单和完整复制目标。文中的“当前”均指本次归档时点。

## 2026-10-20 标准路径修订

以下为原归档之后的执行标准，原交互清单和全部验收范围继续保留。

每次确认制作后（含首次制作、返修和对象参数迭代），受信执行端先创建或载入已批准的 Godot 工程，核对内置 `godot_mcp` 完整且启用，在隔离副本启动普通编辑器，通过 MCP 初始化、工具列表和精确工程路径检查，确认编辑器停止后才启动制作 session。新工程脚手架使用同一标准命令。仅复制插件、勾选启用、恢复模式导入或启动游戏均不算 MCP 就绪。

等待阶段增加“正在准备 Godot 工程并确认编辑器 MCP 就绪”及就绪活动反馈。检查失败不启动制作；编辑器停止未确认时保留占用并显示状态待核实。策划、批准、独立验证、候选试玩和用户接受仍是各自的步骤。点击“创建项目”建立业务记录，实际 Godot 工程在已批准输入准备阶段创建或载入。操作与证据见 [Godot MCP 标准路径](GODOT-MCP.zh-CN.md)。

## 制作主线与归档时项目状态

当前制作主线是：

**创建或选择项目 → 提交想法 → 策划问答 → 审阅方案 → 确认并制作 → 查看验证结果 → 试玩候选 → 接受版本或继续修改 → 对象级迭代。**

## 主要制作流程

| 阶段 | 用户的前端交互 | 页面反馈与后续 |
| --- | --- | --- |
| 1. 创建或进入项目 | 填写项目名称，点击“创建项目”；或点击已有项目的“继续项目” | 进入对应项目，顶部显示阶段、等待谁处理及下一步 |
| 2. 配置策划与制作 | 展开“策划与制作设置”，分别选择模型、推理档位、最长执行时间、软 token 阈值，保存角色偏好 | 设置影响后续执行；正在运行的任务继续使用已冻结配置。归档时服务的模型目录暂无可用项，设置区会提示 |
| 3. 描述游戏想法 | 在“用户原始想法”输入需求；可添加图片并选择概念、风格、布局或素材用途，也可移除附件 | 文字形成本地草稿；点击“梳理我的想法”才提交策划 |
| 4. 回答策划问题 | 阅读 AI 问题，通过选项、文字或数字回答，点击“提交回答” | 进入下一轮策划，更新方案修订；策划进行时显示等待状态 |
| 5. 审阅方案 | 查看“你的要求、AI 准备怎样做、影响谁、保持什么、怎样验证”；展开完整对象、任务及差异 | 有遗漏时填写补充，点击“提交补充并继续讨论”，形成新修订 |
| 6. 确认并派发制作 | 勾选已阅读方案与制作范围，点击“确认方案并继续” | 冻结当前方案和范围，并接续派发制作；页面展示冻结表单 |
| 7. 等待制作与验证 | 查看顶部状态、作业进度；按需展开“执行监视”和诊断 | 区分排队、制作、验证、整理结果、失败及状态待核实；可请求取消或对账 |
| 8. 查看候选结果 | 阅读变更摘要、对象映射、验证结论；展开原文和技术证据 | 看清本轮目标、实际结果、未验证事项及下一步 |
| 9. 试玩候选 | 点击“在 Godot 中运行此候选”；体验后填写相关反馈的决定和理由；可停止试玩 | 试玩对应具体候选。技术检查通过与用户体验决定分别记录 |
| 10. 决定当前版本 | 点击“接受为当前版本”，或“继续修改此候选”；测试环境使用对应测试文案 | 接受后更新工作台版本；继续修改则保留原已接受版本。这里的接受不等于导出或上架游戏 |
| 11. 进入迭代 | 点击“进入迭代工作台” | 以已接受版本作为下一轮调整基线，优先展示对象预览和意见编辑 |

## 迭代工作台交互

| 用户任务 | 前端交互 | 内容如何进入制作流程 |
| --- | --- | --- |
| 找到目标 | 切换场景、浏览对象导航、搜索名称或精确 ID、分类筛选、点击关系链接或画布对象 | 明确当前选择的是项目、场景、实例、共享定义或其他对象 |
| 理解对象 | 查看详情、来源、关联对象；切换 Design／Narrative／Art 视角；按需读取绑定资源 | 分别展示意见目标、已知修改影响、运行存在方式和生命周期 |
| 修改参数 | 编辑当前项目声明支持的字段 | 旁边显示来源当前值、本轮期望、单位、范围和步长；修改先留在草稿中 |
| 填写多目标意见 | 在“本目标意见”输入；或展开分类意见，选择一般／问题／视觉／行为并“加入修改清单” | 意见分别绑定原目标，切换对象后仍保留 |
| 提出结构调整 | “提议新场景”“提议新实例”；放置、移动、微调或提出移除实例；调整实例约束及场景过渡 | 形成结构提案。支持的布局预览可先查看，再“应用到本地草稿” |
| 检查统一申报 | 点击“预览统一申报” | 弹窗汇总意见、属性净变化和结构提案；可编辑、移除、定位原目标，或取消预览继续工作 |
| 提交本轮调整 | 点击“交给当前 Agent 流程” | 先进入新一轮策划，再经过问答、方案审阅和确认制作；草稿编辑本身不会修改游戏工程 |
| 追踪处理结果 | 查看按提案、修订、作业和候选分组的结果；展开历史、原文及证据 | 当前相关结果优先，历史只读；可“回到原对象继续调整” |

## 草稿与异常处理交互

| 场景 | 用户可用交互 |
| --- | --- |
| 日常草稿保全 | 编辑时自动保存；刷新、切换对象或返回项目后恢复对应内容，页面提示保存状态 |
| 主动保存与恢复 | “创建／更新恢复点”“恢复到恢复点”“导出草稿” |
| 撤回操作 | “撤销”“重做”；重置影响整个当前项目／版本工作草稿，恢复点保留，可撤销重置 |
| 存在另一份草稿 | “比较并选择”，先查看对象与内容差异，再选择保留本页、采用另一份或稍后处理 |
| 发布版本变化 | “检查草稿重关联”，预览差异后选择保留旧稿或更新草稿基线 |
| 申报受阻或失败 | 弹窗区分“未发送”“服务明确拒绝”“结果待核实”“上下文已变化”；提供原因及相应入口 |
| 提交结果未知 | 使用“核实原命令状态”，查询原命令；已有待审候选时可直接进入候选审阅 |
| 制作或策划异常 | 查看诊断、请求取消、对账；初始制作失败时可“沿用原输入重新策划”，先编辑再手动提交 |
| 项目管理 | 重命名、归档、恢复归档项目、返回“所有项目”；项目切换保留各自草稿与历史 |

工作台中的参数、意见、结构预览都先表达**本轮意图**；真正改变当前游戏版本，需要经过策划确认、制作、验证和用户候选决定。
