## 词达意与数据契约

新增 `visualReferences`，随 `concept.submit`、`iteration.submit`、`proposal.revise` 进入现有方案、冻结输入和 planner/producer 输入；同步扩展命令及项目读模型 schema。

```json
{"assetId":"asset-id 或 null","intent":"采纳用途","targetObjectIds":[],"preserve":"需要保持","unknown":"尚未确定"}
```

每轮最多六张图、十二条意图。每张选图必须有明确用途，目标必须属于该轮对象文档；只读卡逐图显示本版对象名称与 ID，无对象绑定时标明本轮项目视觉方向。取消图片时保留文字用途、保持项、未知项及关联目标；`assetId:null` 表示文字视觉要求。旧上传用途仍兼容，新增生成图没有采纳用途时不能提交。问答/补充不再用空图片数组误清已有参考；旧客户端仅修改 `assetRefs` 时仍保留文字视觉要求。

原文与 AI 解释分别保存。冻结表单保留 `userText`；统一申报审阅和提交读取同一快照。候选读取精确 project/job/packet/proposalRevision；绑定矛盾或缺失时明确未知，不套用后来草稿。数值冲突处理中，保留控件草稿，但原文优先或待澄清不产生确定的执行数值。

概览/详细是只读密度选择，不是两个编辑器。React 不拥有第二套业务存储或提交器；父层重绘移除挂载点及应用退出时卸载 root。概念草稿复用现有存储的变化检查，另一页面保存后不覆盖或删除新稿；冲突时提供两份内容的只读复制入口。此机制不宣称提供跨进程事务锁。

## 受信生成与截图入口

| 接口 | 行为 |
| --- | --- |
| GET `/api/projects/{projectId}/concept-references` | 读取持久化请求，不调用 ImageGen |
| POST 同路径 | 显式生成；同请求编号/内容幂等，跨项目或内容变化拒绝复用编号 |
| POST `/api/projects/{projectId}/concept-references/{requestId}/reconcile` | 只核实本地已存在文件，不再次收费调用 |
| GET `/api/projects/{projectId}/candidates/{candidateId}/visuals` | 读取该候选的截图及来源 |
| POST 同路径 | 受信上传图片和完整采集条件；仅待审阅候选可新增，历史只读 |

生成协调位于 `backend/concept_references.py`，复用独立的 `tools/imagegen_cli.py`，没有向通用 CLI 加入 Studio 数据库业务。浏览器及制作 Agent 不接收 provider 凭据。生成图不进入运行素材包，不自动创建资源绑定。

先保存原请求编号/正文再 POST。刷新、展开、恢复和只读核实不生成。结果不确定时保留原编号；“使用原请求编号核实收单”明确说明：此前未收单时会执行原请求一次，已收单则返回已有结果。服务重启将未完成请求标为待核实，不自动重投。只有本地配置检查明确未调用 provider 才标失败；其他不确定结果不假定未收费。错误不向产品页面公开私密日志。

图片完整解码，验证实际 MIME、尺寸及大小，限制 5 MB 和 1600 万像素，不用 CSS 尺寸冒充文件合格。完整比例显示，不裁掉主体。导入资源与生成结果记录在同一事务中保存。

截图位于 `backend/candidate_visuals.py`。绑定 project/job/packet/proposalRevision/candidate/Git；场景、视口、相机、状态/操作及采集时点必填，不清楚可明确写未知。标注 `operator-supplied`、`conditionsVerified:false`，不把操作员声明冒称引擎已自动核实。图像损坏、读取失败和条件不可比均不产生视觉通过结论。新增接口复用已有操作员令牌、来源限制和上传边界。
