文档日期：2026-10-09。适用接口版本：`r4-local-1`；实现基准：Git 提交 `13b3a03`。后续版本如果改变界面、适配器或存储结构，需要同步更新说明书。

## 本机已有环境的快速启动

以下命令适用于已完成部署的这份仓库。首次安装先按部署说明书准备 Python、依赖、Git、Godot 和可用的 Codex 模型配置。

```bash
cd /Users/typ/Desktop/godot_project/ptah-gm/local-codex-handoff-20261008-compact
./start-studio.command
```

也可在 Finder 中双击仓库根目录的 `start-studio.command`。启动终端应保持打开。在浏览器访问 [本机工作台](http://127.0.0.1:8765/studio/)。地址必须使用服务对应的 `127.0.0.1` 和端口。

在另一个终端进行只读检查：

```bash
curl -i http://127.0.0.1:8765/api/workspace
```

收到 HTTP 200 表示服务响应。能力标记为 `READY` 仍需分别核对模型认证和 Godot 的实际运行环境；健康检查不需要创建游戏或确认候选。

如果启动报端口占用或 `SERVICE_ACTIVE`，先检查是否已经运行服务，按部署说明书处理。不要重复启动同一状态目录。

## 第一个 Demo 的操作顺序

1. 打开正式工作台，确认顶部没有“测试工作区”横幅。
2. 选择“创建一个新 Demo”，输入概念，可添加受支持图片，点击“梳理我的想法”。
3. 回答围绕收集挑战模板的澄清问题，核对本轮范围。
4. 确认工程初始化。这个单独 session 只生成并发布已验证的准备基线，尚不可玩。
5. 初始化返回后，阅读并确认新的玩法提案，进入另一个制作 session。
6. 等待独立验证，阅读候选报告，在 Godot 中体验候选，然后由用户选择接受或拒绝。
7. 接受后，在当前工作台填写下一轮参数或自然语言调整，重复澄清、确认、制作和审阅。

详细按钮、状态解释和恢复方式见用户说明书。文档中的候选审阅截图来自隔离测试，已作标注。

## 数据与责任

| 内容 | 保存位置 | 维护方式 |
| --- | --- | --- |
| 工作台程序与说明书 | 当前软件 Git 仓库 | 用 Git 提交、版本身份和差异审阅管理 |
| 项目、提案、审批、制作证据与发布快照 | 后端 `.workbench/`，或启动时指定的 `--state-root` | 停服并确认受管执行结束后，完整备份状态根目录 |
| 尚未提交的迭代草稿 | 当前浏览器、当前来源的 IndexedDB | 保留浏览器配置；重要文字自行复制保存 |

软件 Git 提交不能代替后端状态备份；后端备份也不包含浏览器草稿。恢复服务数据应保持原绝对路径，当前没有自动搬迁、数据库迁移或恢复工具。构建与维护遵守[仓库执行约束](../AGENTS.md)，使用 Git 管理版本，不运行独立 SHA/MD5 校验。

制作范围确认、自动 Godot 验证和用户候选接受是三个不同记录。测试记录不能充当正式批准；部署人员与自动探针不代替用户作出游戏决定。

## 当前适用边界

当前交付面向 macOS 本机使用，仅支持收集挑战模板：WASD/方向键移动、收集获胜、超时失败、R 重试。可调整目标数量 1–8、时限 10–300 秒、速度 60–400 像素/秒。

澄清是模板驱动的结构化问答。图片可作为制作参考，当前不自动生产美术。“接受并发布”更新本机工作台快照；导出、签名、上架、远程服务和任意玩法适配需要另行实现。

旧版静态入口是 `/legacy/`，供阅读历史展示。当前 API 工作流以 `/studio/` 为入口。[原本机安装记录](../LOCAL-SETUP-GIT.zh-CN.md)保留安装与迁移过程，其历史测试状态应结合当前实施记录阅读。
