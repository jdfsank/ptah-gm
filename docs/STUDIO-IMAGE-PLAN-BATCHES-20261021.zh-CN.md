# 分图规划与确认生成

本轮替代旧版直接携带整份方案生成一张检查图的主要使用路径。完整验收基线仍保留在 `docs/acceptance/STUDIO-LEGACY-WORKBENCH-REPLICATION-GOALS.full.zh-CN.md`，本说明不缩减该基线。

## 使用

打开视觉策划只读取已提交依据、规划和批次。已有方案点击“规划本轮图片”显式提交只读规划；正常策划反馈也可附带可选的 `visualPlan`。规划不修改文字方案、讨论修订或冻结记录，视觉扩展无效时单独保存失败记录，有效文字策划继续生效。

面板展示建议数量，以及逐图短标题、80 字以内计划用途、覆盖概念和状态。主体、构图、风格、保持项、未知项、相关材料及实际提示词可展开核对。用户可调整共同风格及逐图说明、选择材料、排序、添加、删除和拆图。编辑属于本次视觉说明，不替换服务端已提交原文。拆图后须分别调整目的和材料，新拆出的图默认不选中。

计划最多十二张，优先一至六张；不同检查目的分图，相关概念可以合并。未覆盖事项在覆盖关系中说明后续安排。一次选择一至六张，点击“确认生成选中的 X 张”后冻结说明、材料、来源和最终提示词，依次生成。图数依据最少充分覆盖决定，不按提示词长度分段。

材料细化为原始需求、本轮已提交调整、讨论条目、方案摘要、对象、字段、需求和已采纳用途。每张图只携带所选材料及共同风格、本图说明；不默认携带整份方案 JSON，也不重复附加同一反馈。每图上限 32000 个 Unicode 字符，超限显示具体图片，必须主动减少材料或拆图，不截断、不自动摘要。

生成结果继续显示计划用途，并注明未经读图验证；没有新增自动读图请求。图片默认仅供检查，填写采纳用途、保持项和未知项后才进入参考草稿，经现有原子修订流程提交。每轮最多采纳六图，历史图及冻结记录保留原来源。

## 接口与恢复

- `GET/POST /api/projects/{projectId}/visual-plans`：读取记录或显式创建规划。创建使用 `requestId`、`source`、`preferencesRevision`；同项目不重复创建未决规划。
- `GET/POST /api/projects/{projectId}/concept-reference-batches`：读取批次或确认选图；创建使用 `requestId`、`source`、`visualPlanId`、`sharedStyle`、`images`。每图预分配请求编号。
- `POST /api/projects/{projectId}/concept-reference-batches/{batchId}/{pause|resume|cancel}`：暂停、继续尚未派发项或取消余项。已确认失败项在继续时跳过；结果不明项必须先核实，绝不自动重投。
- 原 `/concept-references` 五字段初始概念及单图请求兼容；批次请求增加计划、图片和批次定位。逐图新请求只能由批次调度派发，重复读取原编号返回原记录。

`visual-plan` 复用 planner 配置、执行器、限流、冷却、停止、核账和进程清理。所有图片入口共用一个串行调度器，最多八个未结束批次，等待项只保存记录。默认 low、1536×1024。每次派发前重新核验来源；失败、来源更新或结果待核实暂停批次，保留完成图片。

刷新、切换项目和断网恢复均读取原编号。服务重启把活动批次暂停，核实原请求后须显式继续。归档只读。未提交回答、READY 补充及工作台草稿不进入已提交材料。
