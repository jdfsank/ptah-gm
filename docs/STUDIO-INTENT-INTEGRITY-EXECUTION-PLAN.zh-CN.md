## 3. 始终成立的交互与数据规则

### 3.1 输入归属和草稿保护

- 对象反馈从开始输入时即绑定稳定目标；切目标前保存旧目标输入，再加载新目标输入。点击添加不得把前一目标的文字改绑到新目标。
- 目标意见、未添加反馈、申报内编辑、澄清回答、READY 补充均保留所需的目标或修订身份。继续复用 DraftStore，只补必要的可选草稿字段，不新增输入存储服务或历史档案体系。
- 澄清与补充使用现有 store、project 上下文，带 proposal、修订和 question 身份。同一修订刷新可恢复；问题变化时不误用旧答案，保留原文字供核对，不为此增加整套旧修订管理界面。
- `input` 时保存模型，照顾中文输入法组合态；重绘从模型恢复，不把销毁 DOM 当成丢弃输入。存储失败仍保留页面内容及导出/复制入口。
- 历史快照须完整复制现有草稿内容，继续复用现有 history。一次添加、移除、编辑、放置、拖拽或重置形成对应事务；不把后端任务状态或批准记录纳入撤销。仅浏览、折叠和主题切换不进入内容历史，输入框原生文本撤销继续保留。

### 3.2 审阅与发送

- 第一阶段采用明确规则：申报中有尚未写回的内容变更时，主提交禁用，提示“完成编辑／取消编辑”。只是打开编辑器且内容未变不阻止提交。缓冲文字仍受草稿保护，不能发送旧文本；完成编辑和更新预览合为一次动作，不增加额外确认弹窗。
- 完成编辑后重新生成预览。相关内容、目标、范围或基线变动使审阅失效；纯导航、主题或折叠不使其失效。
- 用户确认后，将该次审阅数据接入既有提交副本和 sendCommand 路径，保证实际请求与审阅一致。仅修复重复读取造成的不一致，不新建冻结服务、第二份持久提交记录或一套并行回执。
- 保留现有 commandId 幂等及未知结果核账。发送后新输入属于下一份草稿；收到回执只处理本次冻结内容，不清除后来新增内容。

### 3.3 用户决定的有效期

- 决定在现有草稿中保存其依据：对象、字段值、相关意见原文和身份、范围及基线上下文。用内容副本或局部修订比较即可；不要求每个执行角色新增决定状态，不增加独立 hash 检查。
- 只有相关内容变化才使决定失效；不能用可变时间戳或一次普通重绘使其反复失效。
- 失效决定保留原文并标明失效，不能继续作为有效指令发送；无需新增独立决定历史。旧草稿里无法核对的决定仅在相关待处理项处重新核对，不让用户重审无关内容。现有换版重关联和方案审阅能完成的确认不再重复索取。
- 同目标出现参数与原文默认并列保留。“两项都执行”适用于互补意图；明确的同一属性矛盾仍须决定或澄清。自由文字无法可靠判断时交已有 planner 澄清，不在前端引入一套猜测语义的规则引擎。

### 3.4 范围、约束及事实边界

- 每条修改同时保留结构化差异、原文、稳定身份和版本关联。按目标实际能力提供当前实例、当前场景或所有同类等有意义的范围，并列出已知影响对象；不要求每类对象都实现三种范围。未实现局部配置时仍允许表达局部意图，交 Agent 分析后审阅，不能伪装成已支持或直接扩大。
- 暂不能实现局部修改时，保留局部意图，由 Agent 说明独立配置等所需变更；不得自动扩大成共享修改。
- 保留现有固定、可微调、自由的操作语义，并清楚解释适用动作。当前后端 fixed 同时限制移动和删除，不能改称“仅位置固定”后放开删除。运行时角色移动另行说明；改变锁定本身沿用已有 set-lock 条目。先复用现有校验，不重建权限系统。
- 当前值、草稿期望值、制作结果分别呈现，并标明已接受版本、返修候选或源码投影等来源。示意中的即时变化不能显示成真实工程已生效。

## 7. 验证设计与既有测试缺口

## 8. D 类实际执行与最后验收场景

前三阶段的静态检查不能直接关闭 D 类。第四阶段按实际缺口和受影响路径补证据：

1. 原三类真实闭环记录继续保留。核对本轮变更对各形态消费/结果链的影响；未受影响的证据注明版本和复用理由，有影响的形态重跑。若三类均受影响则三类均重跑，不能仅凭旧PASS跳过；不默认重新启动全部三类Agent。
2. 用户只改一个实例，其他同类保持不变；必要的独立配置明确进入已审阅方案，并检查实际源/运行结果。验证“奖励更醒目，但数量保持不变”的保留条件；不能仅查目标文档值。
3. 优先用同一笔受影响的混合提交覆盖参数、原文和结构操作，再在同一上下文继续调整一次。未验证/未满足状态优先用已有真实记录或最小结果fixture核对，不为制造缺陷专门开一次制作。整体PASS或整版接受不能自动解决遗留项。
4. 大量对象/多场景仍属原目标，使用当前项目和已有多场景fixture检查导航与编辑，记录实际规模；已有样本不够时才增加有代表性的数据。不硬设200目标/3场景，不为此新增压力测试平台，不外推容量结论。
5. 首次使用者独立完成：改参数、增加条件、限定局部范围、恢复误操作、审阅未完全满足的结果。观察是否能回答“改的是谁、影响谁、是否生效、哪里没完成”，并记录误操作和需要帮助的位置。

Casino 贯穿示例沿用原报告：“预警改为2秒；奖励更醒目；奖励数量保持不变”。先核对当前项目权威源的实际值，不能硬编码历史的1.5秒作为本次事实。时间线、原文和保留条件进入同一清单；方案说明影响；制作后返回对应效果、验证限度、试玩入口和继续调整。

本批必须有逐项状态、试玩方式和“继续调整”，整版接受不得自动解决所有意见。独立的逐项“满意”按钮及其新命令/持久化不是原完整目标的必需前置，先作为体验增强后置；如以后确需加入，再绑定条目和版本并复用既有记录，不预建评价系统。未验证、受阻和遗留意见继续保留。
