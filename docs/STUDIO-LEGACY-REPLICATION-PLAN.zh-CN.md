## 3. 按用户价值步进实现

### P1：先让用户找到一个元素，并安全地写下修改

**结果**：打开既有项目即可按名称/精确 ID 查找、筛选、浏览父子与关系，选中的同一稳定目标控制工作区、详情、DNA 与意见；切目标、刷新、中文连续输入不丢原文。不等待完整场景画布才能交付该价值。

前端独立范围：在 `frontend/studio/index.html/studio.js/studio.css` 中建立 target selection/router；复用 objectItems、已有字段控件与 DraftStore。增加分类导航、面包屑/深链接/前进后退、关联跳转/使用处和返回位置；DNA 只切观察面。逐目标保存原文与输入草稿，事件携带捕获的 targetId；不在打字时重建编辑 DOM。只读也有意见入口，缺叙事/表现有明确提示。草稿结构升级必须兼容现有已保存内容。

后端可并行范围：在 `object_protocol.py` 的严格合同上增加兼容可选语义描述及 catalog 透传，按实际可用信息声明定义/实例/入口/行为/状态/生成/资源/场景/过渡/预设；补来源类别、关系及局部/共享影响范围。同步 `contracts/` 中实际使用的 schema、planner 指令、catalog 和测试，避免 Python 认可而 JSON schema 拒绝。保留当前 objectId，不直接复制旧版带冒号的 ID，也不允许从名称重新推导身份。

双方最小接口先定：targetRef 指向现有稳定 objectId 或显式稳定子目标；kind 与 facet 分开；sourceRefs、relation、preview、capability 的缺省均为“未声明”。意见含稳定 itemId、targetRef、rawText、scope/context；原文独立于 Agent 的 interpretation/decision。旧 v1 客户端可以继续工作，不能无版本声明静默破坏严格字段集。

**验证出口**：真实项目至少一条场景/系统→对象→行为/资源→使用处→返回路径；两个对象各输入中文，切换、刷新后内容和 target 对应；改名/重排不改意见归属。后端仅针对身份/引用/兼容和持久原文运行必要测试，不制造无价值检查平台。

### P2：补齐 Casino 语义与有来源的元素预览

**结果**：用户能看懂当前游戏，而不是浏览一份文件清单。定义、实际放置/入口、生成规则和短命实例分开；同一环境的不同配置不自动变成多个场景。

先从当前项目 view/snapshot/repairContext 的 sourceCommit 定位权威工程，再交叉检查设计、场景、源码、配置、资源绑定及已有运行证据。`docs/STUDIO-CASINO-INPUT-FIX-20261013.zh-CN.md` 的项目为 `project-3fb9a45e958d457bbf425f7db2e05616`；仓库 `output/moonlit-casino-onetap/` 是另一份“月下赌场”工程，不能未经核对冒充当前 Casino 或直接灌入其素材/五房/敌人设定。目标工程身份若变化，应记录当前项目映射，而不是沿用示例。

将玩家、各类敌人、武器/攻击/成长、投射物/特效、回合/环境、骰子、UI/表现关系逐项提取，覆盖默认、创建、变化、奖励、清理与失败路径；没有来源的内容保持缺失/推断/提案。每条关系可双向查看，每个影响范围可解释。覆盖报告列出“扫描范围/已映射/排除原因/未映射”，不以文件数或零 unmapped 宣称全游戏穷尽。

实现最小而完整的语义预览 renderer：场景/实例构成、资源/图集/首帧、连续运动、动作时间线、响应、交互、状态规则、生成条件与清理。预览合同至少说明类型、来源、模式（静态/推导/浏览器示意/真实 Godot）、能力缺口和播放状态。程序绘制用真实参数与几何/符号示意；未绑定图像不补造素材。有证据才显示阶段/效果窗口；改变参数更新预览，切换目标/关闭要停止播放、高亮与计时器。

**验证出口**：Casino 每个目标类至少走一条实际操作；骰子预警→生效→奖励/清理、敌人生成→定义→行为→表现、武器→攻击→成长分别对照源证据；程序绘制对象与缺图对象都能理解。旧版图集/剪辑预览在真实有此资源的适配数据中保留，不能因 Casino 暂缺美术而删除通用能力。

### P3：一份可恢复、可核对的统一申报单

**结果**：用户多目标写意见或改参数后，能看完整净差异、原文、作用范围、关联预览和冲突，修改/移除/定位后一次提交至现有流程。纯自然语言、纯参数、混合三种路径都成立。

前端以同一 workspace revision 计算净差异，意见与字段变更合并为 item；原值恢复后条目消失；空白意见不形成任务。统一申报模态应支持全部原文、差异前后、共享影响、孤儿重关联/移除、字段与原文矛盾的明确展示与解决。无法可靠自动判断语义矛盾时，保留双方供现有 planner 形成显式 conflict/clarification，不能偷偷删除其中一方。

复用 `sendCommand/iteration.submit` 的持久化 envelope、commandId 和精确查询。冻结用户看过的内容；内容/意见/作用范围/基线变化使预览失效，纯导航/主题不失效。取消不 POST；重复点击不生成新任务；状态未知核对原 ID，不自动重发。现有制作前的必要审阅继续存在，用户只在同一工作台处理它；同一有效授权复用，不要求把同一需求重填两遍。

增加可撤销 workspace transaction：数值、意见编辑、批量/提案应用、重置/重新打开具有清楚范围；保留输入框的原生文本撤销。补显式保存/打开/重置、当前/原文/备份导出；导出说明其为工作台草稿或提交记录，不能声称可运行 Godot 工程。项目/store/version 隔离，加入多标签变更提示与比较后保存；不兼容/存储失败保留现有内容并提供导出。冻结提交记录和之后新增草稿分别保存，结果回流不覆盖新输入。

后端保留逐 item 的稳定身份、原文、明确范围和关联上下文，通过已有 proposal/tasks/requirements/feedback 保存决定，避免为此新建平行任务模型；服务端再次拒绝真正空任务、失效引用和未授权扩大作用范围。

**验证出口**：实际浏览器完成三种提交的预览/取消/确认、编辑回原值、混合多目标、孤儿与冲突；重点击/超时/刷新核账不重复任务；预览后内容改动需重看而导航不打断；模拟存储失败仍可导出，提交后再输入不会被结果刷新覆盖。

### P4：恢复场景编排、独立过渡与提案直接操作

**结果**：旧版所有直接操作路径都可走，并作为同一申报单的结构差异进入真实 Agent 范围。

以 P2 的场景/实例模型实现总览、有向连接与编排画布；背景、世界边界、锚点、坐标、大小、网格、辅助标记一致。浏览和新增明确分开；新场景支持空白/最小结构、实例放置预览/取消、删除草稿实例；玩家定义与入口分开，已有入口只选中。拖拽每次提交一个 transaction，pointer cancel/Escape/失败还原整个动作。

同一约束函数覆盖手动移动、坐标、批量及 Agent 提案：固定、可微调、自由及边界/锚点规则明确。旧版“可微调示例 ±80px”保留为可声明的约束示例，实际项目规则由能力声明确定，不能无理由硬编码所有游戏为 80px。共享定义/资源修改和局部覆盖分别列出影响对象。

出口可选目标场景/入口/条件，引用错误显式显示；未实现条件为“期望”，不能作为已生效门禁。每条有向过渡独立，未设置/无过渡/预设引用三态，目标入口和共享预设可查看/评论；两个方向分别处理。过渡效果为浏览器示意时明确标示。

恢复提案预览→差异→应用/取消→成组撤销/重做。旧版两种预设演示准确保留其演示身份；一般自然语言调用现有真实 planner，而不是给自由文本套预设规则。旧修订提案不得覆盖之后编辑；应用后的净变化进入 P3，不能成为另一个提交入口。后端将 create/delete/move/reference/transition 的结构操作纳入现有规划与允许影响范围，锁定约束也必须在服务端核对。

**验证出口**：旧版新场景、放置、取消、选已有入口、拖拽/坐标、固定排除、出口引用、双向过渡、示例提案应用/过期、成组撤销重做全部可重走；至少一个结构操作通过真实 Agent 改源并验证，浏览器画布变化不算源写回。

### P5：真实 Agent 逐项结果与连续迭代

**结果**：申报后仍停留在原工作台，知道谁处理、哪里受阻、每项做了什么、哪些未完成；不满意就接着改。

沿用 B3/B4 的 planner/producer/verifier/用户审阅角色和现有 Git 交付证据。在现有报告增加 item→处理决定→相关源码变化→验证证据→未完原因/澄清→原目标的追踪。field/结构操作与意见同样需要 item 结果，不只 feedback 有决定。收单、Agent 回合结束、源码已改、技术验证通过、等待体验、用户认可分别展示；总体 job 成功不能把每项自动标完成。

结果链接回原目标及原文/提交时预览，展示相关 diff 和验证来源，并保留本轮之后草稿。失败/缺映射/能力不足/未验证项保持可操作需求，保留原意继续提交。拒绝现有候选时继续沿用当前上下文/repairContext，只调整界面连续性，不增设平行返修工作方式。已有效的用户决定按原有边界复用；仅对实际新增或变化的范围请求必要决定。

**验证出口**：在当前真实项目完成纯参数、纯自然语言、多目标混合各一次完整处理与回流；至少再进行一轮修改，保留前后 item 关联和提交后新输入。每项核对真实 source diff/独立验证/用户待审状态；另走一个明确受阻或失败后的保留与恢复路径。测试数据、mock runner、预设 AI 与浏览器演示分别标明，不能凑为这三次真实闭环。
