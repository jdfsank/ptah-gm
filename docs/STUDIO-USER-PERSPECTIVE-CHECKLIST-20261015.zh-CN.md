# Studio 用户交互检查清单

日期：2026-10-15。由主代理在用户模拟检查开始前整理。

本轮任务：一个独立子代理模拟非代码用户，从页面入口实际操作；先检查、出报告，不立即修复。检查不是用户验收，不替代真实用户的决定。

范围来自完整复刻目标、当前操作指南和实际页面控件。下列 89 项完整目标加 36 项当前流程交互，共 125 项，均保留在覆盖表中；项目没有映射的能力不能算已通过。初始状态全部为“待检查”。

每项从五个角度观察：能否找到入口、能否预知结果、能否理解目标和影响范围、出错后能否恢复、能否知道下一步。结果只使用“已检查未发现问题 / 发现问题 / 部分检查 / 未覆盖 / 当前项目不适用”，附操作证据及限制。历史技术测试不算本次体验证据。

## 检查方法与边界

- 一个 GPT-6.1 Sol high 子代理，扮演首次使用的非代码用户，不再委派其他代理。
- 独立测试副本和新浏览器来源；产品代码、正式项目、原候选决定不改动。
- 先自由发现，再按清单补查；需要指南帮助时明确记录，不把阅读源码当作发现入口。
- 使用真实页面操作、DOM 快照和实际查看过的截图；不注入应用方法、不改可见性来完成流程。
- 不为补齐覆盖制造完成状态，不重新跑大规模工程测试或昂贵原生制作。不具备自然触发条件的恢复和异常分支保留未覆盖。
- 输出任务走查、问题严重度、最短复现、预期与实际、影响及全部 125 项覆盖状态。建议只作为后续优先级，不本轮实施。
