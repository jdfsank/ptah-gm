# 目标模式目标：完整复刻旧版工作台交互，形成统一的 Agent 迭代工作方式

日期：2026-10-14（Asia/Shanghai）。

状态：用户已确认的目标说明，可作为目标模式的目标输入。本文描述最终结果与完成标准，不展开实施规划。

## 核心目标

在当前 Studio 中完整复刻 gm non pk 旧版工作台已实现的交互，补全游戏对象、场景实例、行为、状态、生成规则和资源之间的关联，让用户能够直观浏览游戏、选中具体元素、查看可视化预览，并通过结构化操作或自然语言提出修改。

所有修改进入同一份申报单，统一交给 Agent 处理；处理进度、实际变化、验证结果和未完成事项回到同一工作台，用户能够对照原目标审阅并继续提出修改，形成连续、自然的迭代工作方式。

**最终体验：看见元素 → 选中元素 → 理解关联 → 调整控件或描述期望 → 汇总申报 → Agent 改进 → 查看结果 → 继续调整。**

## 目标范围

- 完整范围包含旧版实际具备的导航、场景编排、定义与实例切换、行为查看、参数编辑、资源查看、场景连接、过渡配置、预览、评论、草稿、撤销重做、导出和统一提交交互。
- 本次目标同时包含关联模型和真实 Agent 迭代链路，最终效果应支持实际操作与结果回流。
- 复用当前项目、工程和已有工作流承接修改，不另建独立的候选、基线、返修方案或并行工作流体系。
- 完整性以旧版仓库中已实现的能力逐项对照；旧版明确为示意、只读或模拟的部分应准确呈现，并在真实执行链路中兑现相应能力。
- 旧版游戏中的具体角色、素材、房间数量和机制名称只是参考数据；工作台应服务当前项目，并能复用到其他游戏。
- 分步实现时仍须完成全部范围，阶段性成果不能替代完整目标的验收。

## 必须具备的最终能力

### 1. 完整、可理解的对象拆解

- 按游戏语义组织对象，不以文件、节点、组件或贴图数量代替对象划分。
- 区分共享定义、场景中的具体实例、入口与定位标记、生成规则和运行时临时对象。
- 覆盖玩家、各类敌人、武器、投射物、机关、特效、环境、场景、界面，以及回合、成长、地图变化等非实体系统。
- 对象可以查看其职责、驱动、行为、状态、生命周期、运动、表现资源和依赖关系。
- 能理解对象在哪里出现、由什么创建、如何变化、何时清理、被谁使用，以及修改会影响谁。
- 共享定义能反查所有相关实例、生成规则和资源使用处；实例能回到定义与行为。
- 同一对象的 Design、Narrative、Art 是不同观察面，始终引用同一目标；缺少叙事或表现时如实展示。
- 对象、实例、行为、资源和意见具有稳定身份，名称变化、导航切换和排序变化不会改变关联。
- 设计意图、源码事实、推断、待实现提案和实际运行结果可以区分；缺失或未映射的信息明确可见。

### 2. 复刻旧版的导航与工作区组织

- 保留项目上下文、可折叠导航、中间工作区、右侧当前详情和集中申报入口。
- 从场景进入实例，从实例进入共享定义、行为、资源与使用处，并能返回原位置。
- 支持名称和精确 ID 搜索、分类筛选、面包屑、目标深链接、浏览器前进后退。
- 导航、画布、预览、详情和意见编辑器同步选中同一个目标。
- 切换 Design、Narrative、Art 不改变目标或意见归属。
- 浏览资源与新增放置使用明确不同的动作；查看元素不会顺带创建实例。
- 提供来源查看、覆盖诊断和帮助入口，技术细节按需展开。
- 保留主题切换、导航折叠、草稿入口与变化提示，视图操作不产生游戏内容修改。

### 3. 每类元素都有合适的可视化预览

- 场景总览能查看场景构成、入口出口和有向连接。
- 场景编排能查看背景、实例、世界边界、位置、大小、锚点、网格和辅助标记。
- 对象与资源能查看缩略图、图集区域、真实剪辑首帧、使用处和共享关系。
- 连续运动显示驱动、速度与运动关系；离散动作在有来源依据时显示阶段时间线和效果窗口。
- 被动响应显示触发、反应和恢复；交互显示条件、目标与结果；规则显示状态、守卫和转换。
- 生成规则能说明生成条件、对象类型、位置策略与清理过程；临时对象不伪装成永久放置资源。
- 场景过渡可以查看方向、出口、目标入口、模式、预设和效果示意。
- 支持旧版已有的一次播放、停止与参数变化后的预览更新。
- 明确区分静态资源、参数推导演示、浏览器示意和真实游戏运行；展示实际来源与当前可用能力。
- 程序绘制、缺少图片、资源未绑定或无法预览的元素仍有可理解的语义展示，不使用虚构素材冒充现有资源。
- 切换目标或关闭预览后，旧目标的播放、状态与高亮正确结束。

### 4. 结构化修改与直接操作

这里的“固定修改”指通过明确控件或动作表达修改，例如数值、选项、开关、坐标与拖拽；与实例“固定/可微调/自由”的锁定状态分别表达。

- 支持已声明的参数控件，显示单位、范围、枚举、默认值与错误提示。
- 支持新建场景、空白或最小结构模板、新建实例、放置预览、取消放置和删除草稿实例。
- 支持拖拽移动和坐标精调，使用一致的坐标、锚点与边界规则。
- 保留固定、可微调、自由的操作约束；受约束对象不会被批量操作或 Agent 提案悄悄改动。
- 玩家定义、玩家实例和出生入口分开；添加或选择已有入口不产生重复玩家定义。
- 支持出口目标场景、目标入口和通行条件的查看与修改表达；无效引用有清楚提示。
- 保留独立有向过渡与共享预设交互，区分未设置、无过渡和预设引用；两个方向分别处理。
- 明确修改当前实例、当前场景、共享定义或共享资源的范围及影响，不隐式扩大范围。
- 一次拖拽、批量调整或提案应用可以整体撤销和重做；取消或失败不会留下半笔修改。
- 只读字段依然可以提出修改意见；新增条件或未实现字段准确显示为修改期望。

### 5. 面向所有目标的自然语言修改

- 项目、场景、背景、实例、定义、行为、状态、资源、生成规则、过渡和预设都有合适的意见入口。
- 用户可以只写自然语言，不必先改参数；也可以只改参数，不必补写意见；两者可以混合。
- 意见自动带上当前元素身份、所在位置、相关预览和作用范围，用户无需手工填写内部 ID。
- 保留用户原文；Agent 的理解、建议或摘要另外展示。
- 只读或尚未暴露控件的元素，也可以通过意见要求改变。
- 多个元素的意见各自保存、统一汇总；切换目标、刷新或重绘不会串写、覆盖或丢失。
- 连续输入与中文输入法可正常使用，不依赖失焦才保存最后内容。
- 意见可以编辑和移除；目标删除或失效时明确提示，允许重新关联或移除，不自动扩大成全项目修改。
- 存在歧义时仅澄清影响实际修改的部分；不要求用户重复已经明确的目标、参数和授权。
- 自然语言与控件修改矛盾时，申报单明确展示冲突，保留双方内容，不静默选择其一。

### 6. 草稿、撤销与恢复

- 内容修改与意见进入持续可恢复的工作区，清楚显示未保存、已保存、待提交和已提交状态。
- 保留旧版保存、重新打开、重置、撤销、重做和导出能力；恢复和重置都具有明确范围。
- 提供当前草稿、已保存原文与必要备份的导出，说明导出内容的用途。
- 项目间草稿隔离，多标签页更新有提示；恢复不会直接覆盖较新的内容。
- 目标缺失、格式不兼容和存储失败时保留已有内容，并给出可操作的恢复或导出方式。
- 已提交内容与提交后新增修改分别保留，Agent 返回结果不会覆盖用户后来输入的草稿。
- 恢复页面或重新打开项目不会自动再次提交，也不会重复启动 Agent。

### 7. 一份统一申报单

- 所有结构化修改、自然语言意见和已应用提案汇总到同一份申报单。
- 能查看涉及哪些元素、修改前后内容、意见原文、局部或共享范围以及相关预览。
- 只统计实际净变化，改回原值不留下虚假修改；纯意见提交正常可用。
- 支持多个元素、多个修改类型混合提交，保留每项身份和关联。
- 用户可以在提交前定位原元素、修改意见、移除条目和处理冲突。
- 完全没有内容变化或有效意见时不生成空任务。
- 预览内容与实际发送内容一致；内容或作用范围改变后必须更新预览，普通导航和主题切换不影响预览。
- 取消预览不发送；重复点击不重复收单或执行；交付状态未知时能核对原申报单。
- 提交后显示清楚的收单与处理状态，刷新、断线或重连后可恢复追踪。
- 使用现有工作流承接申报，不要求用户在多个独立方案或重复表单之间搬运同一需求。

### 8. 真实 Agent 处理与结果回流

- 申报单接入当前真实 Agent 流程，携带明确的目标、用户原文、结构化差异、关联上下文与允许影响范围。
- Agent 能处理一般自然语言修改；旧版预设规则演示不能充当真实处理结果。
- 保留当前已经生效的角色边界、必要审阅与用户决定；同一有效授权不重复索取。
- 用户看到谁正在处理、当前进度、是否受阻和下一步可做什么。
- 每项意见和修改都能追踪到处理决定、实际变化、未完成原因或需要澄清的事项。
- 区分已收单、Agent 回合结束、源码已改、验证通过和用户认可，准确表达完成程度。
- 返回后可以定位原元素、查看相关变化与证据，并继续提出下一轮修改。
- 对不满意结果继续沿用同一工作台和上下文；不要求重新描述整个项目或另建一套返修工作方式。
- 无映射、无能力、执行失败或未验证的项如实显示，保留用户需求供继续处理。
- 整体执行成功不能替代每项需求的结果说明；测试通过也不能代替用户对体验的判断。

### 9. 符合直觉的桌面与窄屏体验

- 元素预览与修改入口优先可见；内部协议、执行日志和诊断按需展开。
- 操作前能理解对象与影响范围，操作后能看到草稿变化，提交后能找到原任务结果。
- 当前元素详情只有一份明确上下文，避免多个编辑器同时指向不同目标造成误操作。
- 窄屏在导航、工作区和详情之间清楚切换，保留返回路径，不将三列强行压缩。
- 模态、键盘、焦点、滚动、Escape、撤销快捷键和输入框原生文本撤销正常工作。
- 打开申报单时不误操作背后工作区；关闭后恢复合理焦点与视图位置。
- 长名称、长 ID、长意见、大量元素、空数据、加载与错误状态都能理解和操作。
- 不把浏览器演示、概念草稿或静态证据显示成真实游戏已完成的事实。

### 10. 当前项目适配与通用性

- 当前 Casino 项目应能正确表达玩家、各类敌人、生成规则、武器、回合、环境变化、骰子事件、表现与界面的关联。
- 多个环境配置不自动当成多个场景；敌人定义与动态生成的临时实例分开；武器配置与攻击行为、成长和表现关联。
- 骰子事件等阶段性规则应能呈现实际存在的预警、生效、奖励和清理关系，并指出来源。
- 程序绘制内容按实际能力预览，不假设项目已经具备 PNG 美术资产。
- 通用工作台交互与项目数据分离；接入其他游戏时复用模型和交互，并声明该项目真实支持的映射与操作。
- 保持独立图片 CLI 的内聚边界：作为接受 prompt 并生成图片的工具，可供视觉策划等用途复用，不与本工作台流程反向耦合。

## 典型用户体验

1. 打开项目，从场景或搜索找到一个元素；预览、详情与意见入口同步定位。
2. 查看这个元素的定义、实例、行为、资源、使用处及影响范围。
3. 通过控件直接调整，或写下“希望怎样改变”；也能对其他元素继续操作。
4. 打开统一申报单，查看全部实际差异和意见，处理必要的冲突后一次提交。
5. 在同一界面追踪 Agent，逐项查看结果、实际变化与验证情况。
6. 对照原元素审阅；满意时按现有流程完成，不满意时直接继续描述和修改。

## 完成标准

以下条件应全部满足，才能认定完整目标完成：

- [ ] 旧版全部已实现交互逐项覆盖，包含场景编排、过渡、提案预览、草稿、评论与提交，不遗漏原有操作路径。
- [ ] 当前项目的定义、实例、生成规则、行为、状态与资源关联正确，来源和影响范围可理解。
- [ ] 导航、画布、详情、观察面、意见与结果围绕同一稳定目标联动。
- [ ] 各类元素具有适合其语义的预览，预览类型、真实来源和能力缺口准确可见。
- [ ] 结构化编辑、新建、放置、移动、取消、连接配置、撤销重做与草稿恢复实际可用。
- [ ] 所有可寻址目标可以提出自然语言意见，输入、切换、刷新和删除目标时归属正确、内容不丢失。
- [ ] 纯参数修改、纯自然语言意见、多目标混合修改均可通过同一申报单提交。
- [ ] 净变化、冲突、共享影响、删除目标意见和预览失效等情况处理明确。
- [ ] 真实 Agent 至少完成上述三类提交的完整处理与结果回流，每项需求可追踪。
- [ ] 连续多轮修改可以保持上下文；不满意后直接继续工作，不重复建立独立方案体系。
- [ ] 刷新、重复点击、断线、存储失败、项目切换和提交后继续编辑不会造成重复执行、串项目或覆盖新草稿。
- [ ] 在真实浏览器中验证桌面与窄屏、中文输入、拖拽、键盘、焦点和模态交互。
- [ ] 声明完成的内容具有对应证据，明确剩余问题，不以示例、静态检查或 Agent 自述替代实际结果。
- [ ] 工作台与当前项目既有可用能力持续可用，并遵循项目 AGENTS.md；构建严格禁止独立 hash 检查。

## 完成结果应提供

- 可实际使用的完整工作台与真实 Agent 迭代闭环。
- 旧版交互覆盖情况与最终操作说明。
- 当前项目实际关联模型和元素预览。
- 结构化、自然语言、混合提交及连续迭代的可核对结果。
- 真实浏览器与实际执行的验证记录，以及明确的能力限制和剩余问题。
